# feature-specs/ — 피처 요구사항 노트

> 사용자(팀 개발자)가 피처 개발 중 **자유롭게 작성·수정**하는 요구사항 노트 모음.
> AI 에이전트가 컨텍스트로 읽는다.

---

## 왜 따로 있나 — SPEC.md 와의 차이

| 문서 | 위치 | 성격 | 변경 빈도 |
|---|---|---|---|
| `feature-specs/<폴더>.md` (본 폴더) | 루트 | **진화하는 요구사항 / 결정 진행 중 / 메모** | 높음 (작업 내내) |
| `SPEC.md` | `backend/app/features/<폴더>/`, `mobile/lib/features/<폴더>/` | **확정된 계약** (API/DB/공개 인터페이스) | 낮음 (확정되면 잠금) |

흐름:
1. 시작 트리거가 `_template.md` 복사 → `<폴더>.md` 생성
2. 사용자가 자유롭게 요구사항 적음
3. AI가 읽고 합의된 항목을 `SPEC.md`(계약)와 코드로 옮김
4. 새 요구 떠오르면 다시 `<폴더>.md`에 추가

---

## 룰

- **컨트리뷰터 자유 수정** ([AGENTS.md 절대 룰 1번](../AGENTS.md)의 예외 — 본인 피처 한정)
- 시작 트리거가 `_template.md` 복사해 생성. 직접 만들지 말 것
- 다른 피처의 노트는 **읽기만**. 수정 X
- 깃에 추적됨. 코드와 같이 PR에 포함되어 머지

---

## 파일 명명

```
feature-specs/
├── _template.md       # 복사 베이스 (실제 피처 아님)
├── auth.md            # 피처 폴더명과 동일
├── chat_message.md
└── ...
```

`features/<폴더>` 의 폴더명을 그대로 파일명으로 사용.

---

## AI 에이전트에게

컨텍스트 우선순위 ([AGENTS.md](../AGENTS.md)):

1. `feature-specs/<폴더>.md` (요구사항 노트 — 사용자가 적은 최신 의도)
2. `features/<폴더>/SPEC.md` (확정된 계약)
3. `docs/SCHEMA.md`
4. ...

`feature-specs/<폴더>.md`에 적힌 미정 사항을 **자체 판단으로 코드화 금지**. 사용자에게 결정 요청 → SPEC.md로 승격 → 그 다음 구현.
