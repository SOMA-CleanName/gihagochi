## 1. 개요

### 한 줄 정의

관리자 승인을 거친 아이돌이 자기 채팅방에서 **메시지 1개를 N명의 응원 팬에게 fan-out** 하고, 팬은 1:1처럼 보이는 화면에서 아이돌에게 개인 메시지를 보낼 수 있는 모바일 앱.

### 사용자 / 플랫폼

| 타입 | 가입 방식 | 진입 화면 |
|---|---|---|
| **팬** | 자유 가입 (이메일 우선, 소셜은 추후) | 응원 중인 아이돌의 채팅방 리스트 |
| **아이돌** | 관리자 수동 승인 후 활성화 | 자기 채팅방 |
| **관리자** | 별도 권한 체계 (관리자 웹) | 가입 신청 / 신고 / 사용자 관리 |

플랫폼: **모바일 앱(iOS+Android)** = 팬+아이돌 / **관리자 웹** = 관리자 전용.

## 9. 참고 — 제품 헌법 / 비기능

상세는 [`docs/ARCHITECTURE.md`](./ARCHITECTURE.md) (작성 예정). 여기선 피처 작업 시 알아야 할 핵심만.

### 제품 헌법 (변경 시 전체 재설계)

1. 메시지 진실의 원천은 **DB**. Realtime은 신호 전달용 (best-effort).
2. **아이돌은 관리자 승인 후에만 노출.**
3. 메시지 1개 = **DB row 1개**. fan-out 시 row 복사 X. trigger로 broadcast.
4. **결제 없음 (1차).**
5. 음성 메시지는 단순 재생까지만.
6. **차단 기능 없음.** 신고만 존재.
7. 권한 체계는 **RLS 일원화** (Auth/DB/Storage 동일 정책).
8. 아이돌 답장은 **전체 공개** (F-023).

### 비기능 핵심

- **실시간성**: 메시지 도달 수 초 이내 (best-effort)
- **권한**: 모든 테이블 RLS 필수. Storage 버킷 private + signed URL
- **푸시**: FCM, OS 권한 거부 케이스 케어
- **모니터링**: Sentry 3 프로젝트
- **알려진 한계**: Supabase Realtime 동시접속 Pro 500. fan-out 비용은 `발송 1 + 수신 N`
